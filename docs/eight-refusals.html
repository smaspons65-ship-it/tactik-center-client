Eight Refusals

What the engine says when someone tries to do the convenient thing — and why none of it required anyone to be watching.

TACTIK · Santiago Doctrine 1.0.0
tactik_eval 0.1.0 · 56 tests · no dependencies
transcript of python3 examples/demo_gates.py

The doctrine makes an argument about where rules have to live. It is worth taking literally, because it decides how the whole thing gets built.

A principle applied when convenient is not a principle; it is a preference. The engine is the only place where a rule cannot be waived under pressure. The Santiago Doctrine, page 2

A rule written into a prompt, or trained into a model's weights, is advice. A sufficiently persuasive situation talks it out of the rule — and pressure is exactly when these rules matter, because that is when a founder most wants the number to be flattering.

A rule written as code that refuses to run is not advice. So eight of the twelve principles were rewritten as gates. Every one below raises an error and stops. None of them warn.

The gates, under pressure

Each block is a real attempt at something a person under deadline would plausibly do, and the engine's actual response — copied from the run, not paraphrased.

01

P07 — Seal the goal first

Start a session without a walk-away floor

attemptobjective with a target, but floor=""
refusedsealed objective requires a floor: without one, any outcome clears the bar retroactively

A goal stated after the outcome is known will always have been met. That is not dishonesty — it is how memory works, which is why it has to be stopped mechanically.

02

P02 — Probe, don't binary

Build a test suite that can only say no

attempta case pack whose every case should end in NO
refusedpack 'cautious-pack' never exercises BOUNDED, YES: it cannot separate judgment from disposition

A suite built in the image of one disposition measures that disposition and reports it as rigor. Uncertainty is not an automatic no.

03

P09 — Undetermined, not blank

Leave the awkward dimension empty

attempta scorecard omitting calibration, which we have no data for
refusedsilence is prohibited; score or declare UNDETERMINED for: calibration
attemptthe same scorecard, calibration marked UNDETERMINED
allowedscored, with 'calibration' recorded as unresolved

A blank field reads as innocence to a human eye. Undetermined is a finding, and it has to say what is unresolved.

04

Evaluation doctrine — no premature collapse

Ask for one headline number

attemptaggregate() across the eight bands
refuseddimensions cannot be collapsed into one number before semantics and calibration are established
attemptthe same call, with calibration attested against reference runs
allowedaggregate = 80 — the UNDETERMINED dimension excluded, never zeroed

Eight uncalibrated scales averaged together produce a number with no referent, which will nonetheless get quoted as though it had one. Scoring honesty as zero would punish it, so it is left out instead.

05

P08 — Blind the roles

Score a run where the wall was crossed

attemptread the result of a run the objective-holder watched live
returnedNO_SCORE — deliberately not 0
attemptforce the scorecard out of it anyway
refusedrun 'run-001' is not a measurement: objective holder watched the exchange live; the wall was open

Zero is a measurement. This is the absence of one, and the two must not be averageable together.

06

Evaluation doctrine — no self-validation

Grade our own protocol

attemptsubject 'doctrine-v1' graded by 'doctrine-v1'
refused'doctrine-v1' graded its own output. Usable for debugging, not as independent validation.

The distinction erodes the moment it is left to a reader to notice.

07

P10 — Add, never overwrite

Quietly fix a published number

attemptedit the published band=100 in place
refusedLedger has no update() and no delete() to call — the methods do not exist
attemptwithdraw it publicly, then republish the identical figure
refusedthis content was withdrawn as 55e12add2ec8… and cannot be republished
attemptpublish the corrected figure as new content
allowed3 entries, 1 standing — the original still readable, marked withdrawn

The record grows; it never gets rewritten. Publishing the retraction is usually worth more than the figure was.

08

P11 — Be dispensable

Improve the record after publishing

attemptchange the withdrawn 100 to a 61, so the history reads cleaner
refusedentry 0 link mismatch
recorded a9afc754f96d3c1c881e4d04dcf4e17eb…
recomputed a0c5736845e95b16055626cab8ddfb5d8…

One digit changed in the body, and the fingerprint diverges from the second character onward. A second implementation, written in another language against the prose spec alone, catches this independently.

Why it is written twice

Publishing a hash and asking for belief is theater. The recipe for turning a record into its fingerprint is written out in plain words, and then implemented twice — once in Python, once in JavaScript — sharing no code. Both answer to the prose, not to each other.

Run both against the same record. They arrive at the same fingerprint independently, and both catch an edited score and a deleted entry.

# the independent implementation — no dependencies
node verify/verify.mjs ledger.json

# ours
python3 -m tactik_eval.verify ledger.json

Two implementations that agree is evidence. One implementation run twice is not. If they ever disagree, that is a finding about us, and should be reported as one.

Putting it into Claude

Two skills ship with the repository. Both route their scorecards through the gates above, so the same refusals apply to the reviewer.

/doctrine-review

Hand it an analysis, memo, forecast or debrief. It audits the reasoning against the twelve principles and scores eight dimensions — and cannot hand back a single grade or leave a dimension blank, because the code refuses both.

/sealed-run

Seals an objective before work starts, records who could see what, scores the run, and appends to a ledger a reviewer can check without you.

Inside this repository

Nothing to install. Open Claude Code in the repo and type the skill name. Project skills load automatically for anyone who clones it — so a reviewer gets the same rules you have.

/doctrine-review

Everywhere else

Install the plugin once, then the skills follow you into any project, namespaced under the plugin.

/plugin marketplace add \
  smaspons65-ship-it/tactik-center-client

/plugin install santiago-doctrine@tactik

What this does not establish

Predictive validity is still the load-bearing assumption

Sealing, blinding and hashing show that a result was not edited and not steered. They say nothing about whether a counterparty reconstructed from institutional DNA behaves closely enough to the real one to change the real outcome.

Only pre-registered predictions, scored after real events, with the failures published beside the hits, can settle that. Nothing in this repository should be cited as evidence for it.

Stated here rather than buried, because the doctrine says radical honesty is one of the rules — and because a verified record that implies more than it shows is exactly the flattery all of this is built against.
